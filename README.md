# 🍎 פירות העמק — Triple Digital Workforce (דמו)

דמו עובד של תהליך קליטת הזמנות בוואטסאפ, עד שלב תיעוד התמונות (ללא חשבוניות),
על בסיס מסמכי ה‑PRD וה‑Flow Discovery.

## הפלואו

```
נציג (SOURCE_CONTACT_NUMBER) — מזמין עבור כמה חברות: כרם קפיטל / טריפל / סולראדג'
   │  הודעת הזמנה בשפה חופשית
   ▼
1. סיווג + פרסור + זיהוי חברה עם Claude   (FR-01, FR-03, FR-04, FR-05, FR-06)
   └─ אין שם חברה? הבוט שואל וממתין לתשובה
2. אישור קבלה אנושי + מס' הזמנה אחיד       (FR-02) — <ר"ת חברה>-<ddmmyyyy>, למשל KC-21072026
3. רשימת ליקוט מסודרת לפי אזורים           (FR-07) — עברית / English / ไทย / العربية
4. PDF לקבוצת הליקוט + בקשת תמונות         (FR-10, FR-12) — נשלחות יחד, לכל הזמנה
5. ריאקשן אימוג'י על ה-PDF                 (FR-11) = הדף הודפס, הליקוט החל (תיעוד בלבד)
6. תמונות שנשלחות בתגובה מצורפות           (FR-13) — דף מסומן + משלוח ארוז
```

תוספות ושינויים (FR-09), כולל הסרת פריטים:

- **לפני הדפסה** — נשלח PDF מעודכן (גרסה חדשה) לקבוצת הליקוט + הודעת
  "הגרסה העדכנית ביותר היא גרסה X" בקבוצת התמונות.
- **אחרי הדפסה** (זוהה ריאקשן) — המלקטים מקבלים הודעת עדכון ממוקדת (➕/➖)
  כתגובה על ה‑PDF; בבק‑אנד מופקת הגרסה המלאה לתיקיית הלקוח (לחשבוניות);
  ובקבוצת התמונות מתקבלת התראת "נוספו/הוסרו פריטים אחרי ההדפסה".

בתחתית כל דף ליקוט: 5 שורות ריקות לתוספות בכתב יד.

## דרישות

- Node.js 18+
- חשבון וואטסאפ (רגיל או ביזנס) שיריץ את הבוט — מתחברים בסריקת QR
- מפתח API של Anthropic (לפרסור ההזמנות)

> **למה לא ה‑API הרשמי של WhatsApp Business?** ה‑Cloud API של Meta לא תומך
> בקבוצות ולא בריאקשנים בקבוצות — והפלואו בנוי עליהם. לכן הדמו משתמש
> ב‑[whatsapp-web.js](https://wwebjs.dev) שמתחבר לחשבון וואטסאפ רגיל.
> שכבת הוואטסאפ מבודדת ב-`src/whatsapp/` וניתנת להחלפה.

## התקנה והפעלה

```bash
npm install
cp .env.example .env
# מלא ב-.env: ANTHROPIC_API_KEY, PICKING_GROUP_NAME, SOURCE_CONTACT_NUMBER
npm start
```

ההגדרות כולן ב‑`.env` בתיקיית הפרויקט (קובץ נסתר — `Cmd+Shift+.` בפיינדר):
מספר הנציג (`SOURCE_CONTACT_NUMBER`), שמות הקבוצות, שעת סגירת שינויים,
ורשימת החברות (ברירת מחדל בקוד; ניתן לדרוס עם `COMPANIES` בפורמט JSON).
כל שינוי ב‑`.env` דורש הפעלה מחדש (`Ctrl+C` ← `npm start`).

### ה-CRM: גיליון הלקוחות של פירות העמק (Google Sheets)

ה-CRM הוא גיליון Google Sheets אחד (`CRM_SPREADSHEET_ID` ב-.env) עם שתי
לשוניות: **"פירות העמק לקוחות"** (47 רשומות) ו**"פירות העמק פנימי"**
(אנשי קשר פנימיים). הקריאה היא **לקריאה בלבד** — התוכנה לא כותבת לגיליון.
עם `GOOGLE_API_KEY` הקריאה דרך Sheets API; בלעדיו — קריאה ציבורית לפי שם
לשונית (מחייב שיתוף "כל מי שיש לו קישור — צפייה").

מודל הנתונים:

- **לקוח משלם + משרד** — שם ההזמנה הוא `[לקוח משלם] [משרד]` (למשל
  "מייקרוסופט תל אביב"). לקוח בלי "לקוח משלם" מוצג בשם המשרד בלבד.
  משרדים שונים לעולם לא ממוזגים.
- **סוג הזמנה** — משתנה (כל הזמנה נשלחת מחדש) או קבועה (הזמנת בסיס
  במאגר, שינויים בוואטסאפ חלים עליה; טעינת בסיס: `npm run base:set`).
- **תצוגה** — רשימת מוצרים מאוחדת או חלוקה לקומות (כל קומה בכותרת
  נפרדת ב-PDF, בלי מיזוג כמויות בין קומות).
- **ערוץ ופורמט** — וואטסאפ / גיליון משותף / מייל / מאגר × טקסט חופשי /
  PDF / אקסל / גיליון. ערוץ שחסרה לו הרשאה או לינק מסומן כלא-מוכן
  ולא מוצג כפעיל.
- **טלפון משותף** בין כמה לקוחות (למשל הזמנות דרך FoodiFairy) לעולם לא
  משויך אוטומטית — הבוט שואל לאיזה לקוח ההזמנה.

סנכרון ידני + דוח מוכנות: `npm run crm:sync` (נשמר גם ב-data/crm-report.json).
בכשל סנכרון התוכנה ממשיכה עם ה-snapshot התקין האחרון.

בהרצה ראשונה יוצג QR בטרמינל — סרקו אותו מהטלפון שמריץ את הבוט
(וואטסאפ ← הגדרות ← מכשירים מקושרים). אם שם הקבוצה שגוי, האפליקציה תדפיס
את רשימת כל הקבוצות בחשבון כדי שתעתיקו את השם המדויק.

### מסך בקרה מקומי

עם ההפעלה עולה גם מסך בקרה בכתובת **http://localhost:3010** (ניתן לשמור
כקיצור במסך הבית): סטטוס חיבור חי, הצגת ה‑QR לסריקה כשנדרש חיבור מחדש,
כפתור עצירה/הפעלה של החיבור (הסשן נשמר — לא יידרש QR מחדש), וכפתור
דיווח תקלה שפותח מייל ל‑gal@triplep.co.il.

### בדיקות בלי וואטסאפ

```bash

```

## הדגמה מלאה

1. שלחו הודעת הזמנה מהמספר המוגדר ב‑`SOURCE_CONTACT_NUMBER`, למשל:
   ```
   היי, הזמנה לטריפל למחר:
   2 קילו עגבניות שרי
   בננות 3 קילו רק אם הם בשלות
   מלון קטן 2
   6 קוטג (אם חסר אז גבינה לבנה)
   ```
2. הנציג מקבל אישור אנושי עם מספר ההזמנה (TR-21072026). בלי שם חברה — הבוט ישאל.
3. בקבוצת הליקוט מתקבל ה‑PDF, ובקבוצת התמונות — בקשת התמונות של אותה הזמנה.
4. מלקט מסמן ריאקשן (👍) על ה‑PDF = הדף הודפס והליקוט החל.
5. שולחים 2 תמונות בתגובה לבקשה — ההזמנה מסומנת כמתועדת ✅
6. נסו גם: "תוסיפו עוד 2 אבטיחים" / "תורידו את הקוטג'" — לפני ואחרי הריאקשן,
   ותראו את ההתנהגות השונה בקבוצות ובתיקיית הלקוח.

## מבנה הפרויקט

```
src/
  index.js              # נקודת כניסה: חיבור, ניטור חיות, ניתוב אירועים
  config.js             # קונפיגורציה מ-.env + רשימת החברות
  ai/parser.js          # פרסור הודעות עם Claude (structured outputs + זיהוי חברה)
  flow/orchestrator.js  # הפלואו העסקי: הזמנה→אישור→PDF→תמונות→תיעוד
  flow/replies.js       # נוסחי גיבוי למענים (המענה הרגיל נכתב ע"י Claude)
  orders/store.js       # מאגר הזמנות (JSON) + היסטוריית פעולות (FR-14)
  pdf/template.js       # תבנית HTML של דף הליקוט (RTL, 4 שפות, שורות כתב יד)
  pdf/generator.js      # רינדור HTML→PDF עם Chrome headless
  whatsapp/client.js    # שכבת whatsapp-web.js + עקיפות תאימות (ניתנת להחלפה)
  crm/source.js         # קריאת ה-CRM מ-Google Sheets: מיפוי, נרמול, ולידציה, snapshot
  crm/sheets.js         # גשר ה-CRM אל שאר המערכת (זיהוי לקוח לפי טלפון וכו')
  orders/baseOrders.js  # הזמנות בסיס ללקוחות קבועים (גרסאות + בסיס פר יום)
  parsers/registry.js   # קבצים נכנסים -> טקסט (PDF/אקסל) לפני הפרסור
  channels/registry.js  # סטטוס ערוצי קליטה (וואטסאפ פעיל; מייל/גיליון ממתינים להרשאות)
  web/server.js         # מסך הבקרה המקומי
scripts/                # בדיקות + סקריפטי אבחון
output/<חברה>/          # תיקייה שטוחה פר חברה: Kerem-Capital-[פרט]-ddmmyyyy-Vx.pdf + תמונות
data/orders.json        # מאגר ההזמנות
assets/logo.png         # לוגו לכותרת ה-PDF
```

## מה בכוונה לא בדמו

- הפקת תעודות משלוח / חשבוניות (שלב 4 בפלואו — מחוץ לסקופ)
- CRM / מאגר מוצרים מסודר — הפרסור והתרגום נעשים ע"י המודל בכל הודעה
- ריצה כשירות רקע קבוע (pm2 / launchd) — מומלץ לפני מסירה ללקוח

## ⚠️ הערה

whatsapp-web.js היא ספרייה לא רשמית, וכרגע מוצמדת לגרסת וואטסאפ‑ווב ישנה
(`WWEB_VERSION` ב‑config) עם מספר עקיפות תאימות ב‑`src/whatsapp/client.js`
בעקבות עדכון וואטסאפ מ‑14.7.2026. לדמו זה מצוין; לפרודקשן כדאי לשקול
ספק כמו Green API או שילוב של ה‑API הרשמי במסלולים שאינם דורשים קבוצות.
